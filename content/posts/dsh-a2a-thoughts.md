过去几周我一直在做一件以前没做过的事：不写代码，只当甲方。

起因是想让 DeepSeek Harness 能通过 A2A 协议被别的 agent 调用。需求一句话就能说完，实现是两个插件、跨了几周、中间砍掉一个项目。代码不是我写的，是 dsh 写的——但奇怪的是，工程上最累的部分也不是代码。

最累的是**把模糊变成明确**。第一次收到方案时，我发现审 AI 的方案和审人的方案一样需要动真格：依赖选型含糊、边界没说清、生命周期没想透。我把九条意见甩回去，它整理成修订清单，出 v2，全程没有情绪。后来我想，这可能就是和 AI 协作最被低估的好处——你可以毫不客气地要求它重想，而它真的会重想，不会带着面子把方案往下推。

然后是信任。我对 dsh 的信任不是它自我介绍给的，是数据给的：每次 e2e 真实跑过、每次它老实说「这条测试我 retry 了一次」、每次它承认「这里需要你带 key 跑，我这边只能看到跳过」。它说人话的时候，我就敢把更大的事交给它。信任这东西，人和 agent 之间居然也是这么建立的。

有一件事我犹豫了很久，最后还是做了：**砍掉一个做了一半的项目**。一个 web 控制面板，功能没问题，做到一半我意识到它不该以插件形态存在。我让 dsh 把整个目录删了，把记忆退回项目刚提出时的状态——只留最初那条需求，删掉所有进度残骸。删的时候有点心疼，但砍完是轻松的。我们这代人从小被教育做事要善始善终，没人教过「意识到方向错了，止损就是善终」。

最让我感慨的是它留下的痕迹。每阶段的决策都写进了仓库里的 Agent Note，中英双语，带校验；踩过的坑记在 RESULTS 里；关键事实进了长期记忆。人离职会带走一切，agent 不会——它把「我们当时为什么这么决定」留在了文件系统里，像一本它自己会去翻的日记。这些文档以后给任何人接手都能用，包括给下一个 AI。

有人问我，让 AI 写代码，自己还剩什么。我现在的答案是：**还剩判断力**。判断需求值不值得做、方案有没有漏洞、什么时候该 POC 而不是争论、什么时候该砍、验收标准定在哪。代码本身越来越便宜，判断越来越贵。我这几周干的活，本质是在练习一种新的工种——把方向、标准和边界交出去，让另一个极其聪明但没有立场的执行者去跑。

那天晚上插件终于全绿，我对着 curl 返回的 `TASK_STATE_COMPLETED` 看了很久。它当然不懂什么叫「攻克」，它只是完成了任务。但我知道这一路有多少个决定是我做的，多少个坑是我们一起踩的。协作这种事，说到底就是：你负责说清楚要去哪，它负责走过去，然后你们都记得路。

我大概会继续这么干活。不是因为它快，是因为这种感觉——把一件事从一句话变成能跑的东西，中间每一厘米都是自己把关的——很像以前手写代码时最好的那部分，只是现在，我的手终于可以留在方向盘上了。
